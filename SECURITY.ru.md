# Политика безопасности

[English](SECURITY.md) · [Русский](SECURITY.ru.md)

Русский раздел Security для Remnawave Manager (Корги Люси). Чувствительные ошибки сообщайте владельцу репозитория лично — не открывайте публичный issue с деталями эксплуатации.

## Секреты — не публиковать

Не кладите в Git, issue, PR, чат, скриншоты и pastebin:

- GitHub personal access token;
- API-токены Remnawave и JWT администратора;
- `SECRET_KEY` ноды;
- пароль PostgreSQL;
- пароль администратора панели;
- приватный ключ age (`/opt/remnawave/backup-age.key`);
- пароль Hysteria2;
- токен Telegram-бота;
- Cloudflare API token;
- содержимое `/opt/remnawave/credentials.txt` и `/opt/remnawave/manager.env`.

Пункт **23** / `admin-login SHOW` печатает вход в панель **один раз на TTY**. Пароль **не** пишется в `/var/log/remnawave-manager.log`. Токен Telegram в лог не попадает.

## Как установщик хранит конфигурацию

`/opt/remnawave/manager.env` **не** выполняется через `source`. В паролях бывают `$`, `&`, обратные кавычки и `\`; обычный `source` оборвал бы остаток файла (домены не загрузятся) или запустил фоновые задачи. Установщик разбирает строки `KEY=VALUE` и **не даёт** перезаписать ключи оболочки и самого скрипта: `VERSION`, `PATH`, `HOME`, `IFS`, `LD_PRELOAD`, `DRY_RUN`, `AUTO_YES` и соседние. Аргументы CLI `KEY=VALUE` идут через тот же запрет.

Файл Ubuntu `/etc/os-release` не подключается через `source` (там `VERSION=`, это ломает `--version`).

## Чеклист для production

- Скачивайте **GitHub Latest** и сверяйте SHA256 с `SHA256SUMS` (см. README). Не доверяйте закэшированному `raw.githubusercontent.com/main`.
- Ограничьте SSH (`ADMIN_IP`, пункт **32** / `firewall`).
- При установке на два VDS порт ноды **2222** открывайте только с IP панели.
- Проверьте `backup` / `restore` до аварии. Копия вне VDS: rclone + age (`backup-remote`).
- Сторонние модули из пункта **24** остаются на **их** лицензиях; этот репозиторий их не перелицензирует.
- Если нужна воспроизводимость панели — фиксируйте теги образов, а не плавающий `latest`.
- Удалите `credentials.txt` после того, как секреты сохранены в надёжном месте.

## Заглушка на домене подписки (1.5.5)

Пункт **33** / `sub-stub` отдаёт публичный сайт питомника на `https://DOMAIN_SUB/`. Файлы лежат в `/var/www/sub-site` (HTML, CSS, JPEG/SVG). В этом дереве **нет токенов и паролей**. Пути, которые не относятся к заглушке, в том числе `/shortUuid`, по-прежнему идут на страницу подписки Remnawave. Секреты в `/var/www/sub-site` не кладите.

## Меню и API

- Создание пользователя (пункт **28**) задаёт `expireAt`, по желанию `trafficLimitBytes` и `hwidDeviceLimit`. Лимит устройств `0` не отправляет поле HWID (без ограничения). Трафик `0` — безлимит.
- `self-update` подменяет файл установщика после `bash -n`. Его нельзя гонять в подпроцессе меню (`exec` должен заменить текущий процесс).
- Ошибка пункта меню (`die`, API) возвращает в меню и не должна гасить весь процесс.

## Сообщить об уязвимости

Если ошибка может утечь секреты, обойти файрвол или выполнить чужие команды: пишите владельцу репозитория лично. Рабочий эксплойт до исправления не публикуйте.
